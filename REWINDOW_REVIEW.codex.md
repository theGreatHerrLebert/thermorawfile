**Findings**
1. **Medium: the doc claim is stronger than the evidence supports** at [src/lib.rs:2283](/home/administrator/thermo-raw-spike/thermorawfile/src/lib.rs:2283). The implementation is probably actionable for the audited Tier-2 3a case: same scan count, DIA MS2, Fusion/Astral-style v66 events, and consumers using Thermo API/RawFileReader-derived metadata. If `GetReaction` changes and no filter text exists on disk, most downstream tools that ask the vendor API or mzML conversion for precursor isolation should see the new reaction values.  
   The unsafe part is wording this as globally true: “confirmed the isolation window lives only...” and “no other field needs patching.” That should be scoped to audited layouts/instruments. A non-audited Thermo layout, old RAW revision, different MSn grammar, or a consumer using an independent parser could still disagree. I would phrase this as “for decoded v66 Fusion/Astral DIA layouts validated by audit” and ideally expose/record an audit guard.
2. **Medium: `scan_event_ranges()` mostly matches the event grammar, but its bounds story is weaker than the variable-event walker** at [src/lib.rs:2258](/home/administrator/thermo-raw-spike/thermorawfile/src/lib.rs:2258). The `nprec @ +136`, `56 * nprec`, `nranges`, then `16 * nranges` math matches the grammar already used by `walk_variable_scan_events()` at [src/lib.rs:2434](/home/administrator/thermo-raw-spike/thermorawfile/src/lib.rs:2434). However:
   - `off + 136`, `o + 4`, `p + 8`, and `p += 16` are unchecked additions.
   - There is no `nprec > 16` plausibility cap, unlike [src/lib.rs:2460](/home/administrator/thermo-raw-spike/thermorawfile/src/lib.rs:2460).
   - `nranges_pos + 4` is unchecked.
   
   Slice reads prevent most out-of-bounds reads, but malformed offsets can still panic in debug or wrap in release on extreme values. Mirror the checked helper style from `walk_variable_scan_events()`.
3. **Low: no Rust borrow hazard in `rewindow_in_place()`** at [src/lib.rs:2294](/home/administrator/thermo-raw-spike/thermorawfile/src/lib.rs:2294). `scan_event()` returns an owned `ScanEvent`, so `assign(scan, &ev)` does not leave an immutable borrow of `self` alive when `set_isolation()` mutates bytes. Recomputing scan-index low/high or mass ranges is unnecessary if the audit conclusion holds, because those fields describe fragment scan range / actual peak packet statistics, not the precursor isolation window.  
   One wording/behavior mismatch: the doc says “MS2”, but the code rewrites every `ms_order >= 2` scan at [src/lib.rs:2300](/home/administrator/thermo-raw-spike/thermorawfile/src/lib.rs:2300). If this API is DIA-MS2 only, use `ev.ms_order != 2`.
4. **Low: narrowing width without moving peaks is not a file-format inconsistency, but it is a scientific one.** Readers generally should not reject this: fragment peaks outside the narrower precursor window are normal because fragment m/z range is independent of precursor isolation. The real risk is semantic provenance: the spectrum was acquired under the old quadrupole window, so downstream quant/search may behave as if selectivity was different from reality. Document this as metadata re-windowing/synthetic reassignment, not physical peak transformation.
5. **Low: same-cardinality framing is honest.** `rewindow_in_place()` is exactly `set_isolation()` over existing scans, so it cannot resize windows/cadence. The first real 3b hazard is structural: changing scan/window cardinality means inserting/removing scan events, scan-index entries, trailers/scanparams, and data packets, then relocating section pointers and offsets. If changing reaction count inside an event, the reaction block resize shifts the range/calibration block and every following variable-length event offset.
6. **Missing tests / edges.** Add tests for fixed-stride and variable-length `scan_event_ranges()`, malformed/truncated events returning `None` without panic, implausible `nprec`, `nranges > 64`, `rewindow_in_place()` skipping MS1 and optionally MS3, callback `None`, exact byte-diff limited to reaction fields before checksum, and a round-trip asserting local `scan_filter()`/RawFileReader see new center/CE while `[low-high]` remains fragment scan range.
